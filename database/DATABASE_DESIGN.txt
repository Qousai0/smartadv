SMART ADVISOR - DATABASE DESIGN

الغرض من الملف

هذا الملف هو مرجع تصميم قاعدة بيانات مشروع Smart Advisor. يوضح الجداول،
وظيفة كل جدول، الحقول، أنواع البيانات، المفاتيح الأساسية والخارجية،
والعلاقات بين الجداول.

ملاحظات مهمة قبل التنفيذ

1.  المشروع يستخدم Laravel 9 و MySQL.
2.  قاعدة البيانات الحالية على Aiven تحتوي بالفعل على:
    -   users
    -   roles
    -   specializations
    -   password_resets
    -   failed_jobs
    -   personal_access_tokens
3.  جدول users مبني على Laravel، واسمه يحتوي على الحقل name وليس
    full_name. لذلك سنستخدم name ولن نغيّر اسم العمود الحالي.
4.  تمت إضافة الأعمدة التالية إلى users:
    -   role_id
    -   specialization_id
    -   academic_year
5.  لا تستخدم migrate:fresh أو migrate:refresh على قاعدة البيانات
    الحالية؛ لأن ذلك قد يحذف بيانات موجودة. نضيف كل تغيير عن طريق
    Migration جديدة.
6.  يجب أن يحتوي كل جدول جديد على Primary Key بسبب إعدادات Aiven.
7.  أنواع ENUM المذكورة هنا هي قيم مقترحة. يمكن تنفيذها كـ string مع
    validation في Laravel إذا أردنا مرونة أكبر.
8.  كل جدول أدناه من جداول وظائف المشروع، ولا يشمل جداول Laravel
    الافتراضية.
9.  التصميم الأصلي يحتوي فعلياً على 23 جدولاً وظيفياً، وليس 22 كما ورد في
    ملخص الرسالة القديمة.
10. أضفنا في نهاية التصميم جدول course_materials كتوسعة موصى بها؛ لأن
    المشروع يحتاج حفظ ملفات المواد المرفوعة (PDF والصور وغيرها) حتى
    يستطيع المساعد الذكي الرجوع إليها. هذا الجدول لم يكن موجوداً في
    التصميم القديم.

============================================================ القسم
الأول: المستخدمون والصلاحيات
============================================================

1) users - المستخدمون

الوظيفة: تخزين حسابات الطلاب والمسؤولين. هذا الجدول موجود حالياً في قاعدة
البيانات.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - name VARCHAR(255),
NOT NULL - email VARCHAR(255), UNIQUE, NOT NULL - email_verified_at
TIMESTAMP, NULL - password VARCHAR(255), NOT NULL - role_id BIGINT
UNSIGNED, FK -> roles.id, NULL - specialization_id BIGINT UNSIGNED, FK
-> specializations.id, NULL - academic_year TINYINT UNSIGNED, NULL -
remember_token VARCHAR(100), NULL - created_at TIMESTAMP, NULL -
updated_at TIMESTAMP, NULL

ملاحظة: الحقول الأصلية في Laravel مثل id وname وemail وpassword
وtimestamps موجودة مسبقاً. لا تنشئ جدول users من جديد.

2) roles - الأدوار

الوظيفة: تحديد نوع المستخدم وصلاحياته العامة.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - name VARCHAR(100),
UNIQUE, NOT NULL - created_at TIMESTAMP, NULL - updated_at TIMESTAMP,
NULL

أمثلة name: student admin content_manager

العلاقة: Role واحد يمكن أن يرتبط بعدة Users (One-to-Many).

3) specializations - التخصصات

الوظيفة: تخزين التخصصات الجامعية مثل هندسة البرمجيات.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - name VARCHAR(255),
NOT NULL - description TEXT, NULL - created_at TIMESTAMP, NULL -
updated_at TIMESTAMP, NULL

العلاقات: - التخصص الواحد له عدة Users. - التخصص الواحد له عدة
Courses. - التخصص الواحد له عدة Study Plans.

============================================================ القسم
الثاني: المواد والخطط الدراسية
============================================================

4) courses - المواد الدراسية

الوظيفة: تخزين المواد التي تطرحها التخصصات.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - course_code
VARCHAR(100), UNIQUE, NOT NULL - name VARCHAR(255), NOT NULL -
description TEXT, NULL - credit_hours TINYINT UNSIGNED, NOT NULL -
specialization_id BIGINT UNSIGNED, FK -> specializations.id - syllabus
LONGTEXT, NULL - created_at TIMESTAMP, NULL - updated_at TIMESTAMP, NULL

العلاقات: - كل Course تتبع تخصصاً واحداً. - المادة يمكن أن تظهر في عدة
Study Plans. - المادة يمكن أن يكون لها متطلبات سابقة. - المادة يمكن أن
ترتبط بمواد دراسية مرفوعة واختبارات ومشاريع.

5) study_plans - الخطط الدراسية

الوظيفة: تمثيل الخطة الدراسية المعتمدة لتخصص معين.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - name VARCHAR(255),
NOT NULL - specialization_id BIGINT UNSIGNED, FK -> specializations.id -
version VARCHAR(50), NULL - total_credit_hours SMALLINT UNSIGNED, NOT
NULL - created_at TIMESTAMP, NULL - updated_at TIMESTAMP, NULL

العلاقة: التخصص الواحد يمكن أن يمتلك عدة خطط دراسية.

6) study_plan_courses - مواد الخطة الدراسية

الوظيفة: جدول وسيط يربط الخطة بالمواد، ويحدد الفصل المقترح لكل مادة.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - study_plan_id BIGINT
UNSIGNED, FK -> study_plans.id - course_id BIGINT UNSIGNED, FK ->
courses.id - semester_number TINYINT UNSIGNED, NOT NULL - is_elective
BOOLEAN, DEFAULT FALSE - created_at TIMESTAMP, NULL - updated_at
TIMESTAMP, NULL

قيد مهم: UNIQUE(study_plan_id, course_id) لمنع تكرار المادة نفسها في
الخطة نفسها.

7) course_prerequisites - المتطلبات السابقة للمواد

الوظيفة: ربط المادة بالمواد التي يجب اجتيازها قبل تسجيلها.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - course_id BIGINT
UNSIGNED, FK -> courses.id - prerequisite_course_id BIGINT UNSIGNED, FK
-> courses.id - created_at TIMESTAMP, NULL - updated_at TIMESTAMP, NULL

قيد مهم: UNIQUE(course_id, prerequisite_course_id)

ملاحظة: يمكن استخدام مفتاح أساسي مركب من course_id
وprerequisite_course_id بدلاً من id. أضفنا id هنا لتوحيد أسلوب الجداول
وتسهيل التعامل معها.

8) student_courses - مواد الطالب وتقدمه

الوظيفة: تخزين المواد التي سجلها الطالب وحالتها وعلامته.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - student_id BIGINT
UNSIGNED, FK -> users.id - course_id BIGINT UNSIGNED, FK -> courses.id -
status VARCHAR(30), NOT NULL - grade DECIMAL(5,2), NULL - completed_at
DATE, NULL - created_at TIMESTAMP, NULL - updated_at TIMESTAMP, NULL

القيم المقترحة لـ status: planned in_progress completed failed

قيد مقترح: UNIQUE(student_id, course_id) إذا كان مسموحاً بسجل واحد لكل
مادة. إذا أردنا دعم إعادة المادة وتسجيل محاولات متعددة، نحتاج لاحقاً
لتصميم جدول منفصل لمحاولات دراسة المادة.

============================================================ القسم
الثالث: ملفات المواد والمساعد الذكي
============================================================

9) course_materials - ملفات ومصادر المواد (إضافة موصى بها)

الوظيفة: حفظ بيانات الملفات التي يرفعها المسؤول أو مدير المحتوى لكل
مادة، مثل PDF وDOCX والصور. الملف نفسه يُحفظ في Storage، وليس كـ BLOB
داخل قاعدة البيانات. نخزن هنا مساره ومعلوماته.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - course_id BIGINT
UNSIGNED, FK -> courses.id - uploaded_by BIGINT UNSIGNED, FK ->
users.id, NULL - title VARCHAR(255), NOT NULL - file_path VARCHAR(500),
NOT NULL - file_type VARCHAR(50), NULL - mime_type VARCHAR(100), NULL -
file_size BIGINT UNSIGNED, NULL - extracted_text LONGTEXT, NULL -
created_at TIMESTAMP, NULL - updated_at TIMESTAMP, NULL

ملاحظات: - file_path هو مكان الملف في Laravel Storage. - extracted_text
يمكن أن يحتوي النص المستخرج من PDF أو DOCX أو الصورة بعد OCR، ليسهل
إرساله إلى خدمة الذكاء الاصطناعي. - لا تخزن محتوى الملف الثنائي داخل هذا
الجدول. - يمكن جعل uploaded_by فارغاً إذا أضيف الملف من عملية آلية.

10) ai_conversations - محادثات الذكاء الاصطناعي

الوظيفة: كل سجل يمثل محادثة واحدة بين المستخدم والمساعد الذكي.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - user_id BIGINT
UNSIGNED, FK -> users.id - title VARCHAR(255), NULL - created_at
TIMESTAMP, NULL - updated_at TIMESTAMP, NULL

العلاقة: المستخدم الواحد يمكن أن يمتلك عدة محادثات.

11) ai_messages - رسائل المحادثة

الوظيفة: تخزين رسائل المستخدم وردود المساعد داخل المحادثة.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - conversation_id
BIGINT UNSIGNED, FK -> ai_conversations.id - sender_type VARCHAR(20),
NOT NULL - message_content LONGTEXT, NOT NULL - created_at TIMESTAMP,
NULL - updated_at TIMESTAMP, NULL

القيم المقترحة لـ sender_type: user assistant

العلاقة: المحادثة الواحدة تحتوي على عدة رسائل.

12) academic_recommendations - التوصيات الأكاديمية

الوظيفة: حفظ النصائح والتوصيات التي يقدمها النظام للطالب.

الحقول: - id BIGINT UNSIGNED, PK, AUTO_INCREMENT - student_id BIGINT
UNSIGNED, FK -> users.id - course_id BIGINT UNSIGNED, FK -> courses.id,
NULL - recommendation_text LONGTEXT, NOT NULL - reason TEXT, NULL -
created_at TIMESTAMP, NULL - updated_at TIMESTAMP, NULL

ملاحظة: course_id يكون NULL إذا كانت التوصية عامة وليست مرتبطة بمادة
محددة.

============================================================ ملاحظات
تنفيذية في Laravel
============================================================

1.  كل جدول جديد ينشأ بملف Migration مستقل.
2.  استخدم $table->id() لإنشاء المفتاح الأساسي.
3.  استخدم foreignId()->constrained() للمفاتيح الخارجية عندما يكون اسم
    العمود واسم الجدول متوافقين مع convention في Laravel.
4.  استخدم nullable() فقط عندما يسمح التصميم فعلاً بغياب القيمة.
5.  أضف unique constraints المذكورة أعلاه داخل Migration.
6.  عند حذف سجل أب، قرر بوضوح هل نستخدم cascadeOnDelete أو
    restrictOnDelete أو nullOnDelete. لا تضف cascade عشوائياً.
7.  Laravel timestamps تعني created_at وupdated_at.
8.  كلمات المرور تحفظ بعد Hash فقط، ولا تحفظ كنص واضح.
9.  ملفات المواد تحفظ في Laravel Storage، وقاعدة البيانات تحفظ بياناتها
    ومساراتها والنص المستخرج منها.
10. لا يعني وجود التصميم أن جميع الجداول أُنشئت. التصميم مرجع لخطة العمل.

نقطة البداية الحالية:

قبل تنفيذ أي Migration جديدة، نفحص migrate:status ونتأكد من الجداول
الموجودة. ثم نبدأ بجدول courses لأنه أساس الخطط والمواد والاختبارات.
